# bitproofs

Bit tricks, proved using formal methods. https://festivixy.github.io/bitproofs/

Every entry in the catalog is verified prior to publication. For the proven and best-found entries, the optimal program is proved by the Z3 theorem prover to be equivalent to its specification for all 2^32 possible inputs, and an independent fuzzer verifies the claim prior to labeling; verified-upper-bound entries are checked exhaustively at small widths and fuzzed at 32 bits, exactly as their labels state. The playground runs the same synthesizer in real time in the browser — Z3, compiled to WebAssembly, synthesizes the program for an 8-bit input domain and proves it again for 32 bits.

The engine used is the superoptimizer, called superopt (https://github.com/festivixy/superopt): CEGIS superoptimizer that works on a loop-free integer/bitwise intermediate representation. This repository is a TypeScript implementation of the engine core, gated by cross-check vectors generated by the Python oracle. The TypeScript implementation is considered untrusted until it agrees with Python for hundreds of interpreter runs, for each equivalence verdict, and for each synthesis result. The two implementations use different major versions of Z3, making their agreement stronger evidence, not weaker.

Honesty principles inherited from the engine:

- proven: comprehensive search of all possible program shapes has been performed and there is no smaller viable program form;
- best found: synthesis and verification has been done, the floor is not certified;
- verified upper bound: a hand-built chain has been exhaustively verified at small widths and fuzzed at 32, no minimality claims made;
- optimality floors: determined offline by the Python pipeline; the browser re-synthesizes and re-verifies and makes no floor claims;
- solver timeout leads to 'undetermined' verdict, not a claim.

Inspired by Sean Anderson's Bit Twiddling Hacks and Hacker's Delight. The synthesis technique is component-based CEGIS after Jha, Gulwani, Seshia, and Tiwari (2010).

Build: npm ci && npm test && npm run build. The site is static; deploys run the full cross-check suite first.
